# 参考文案逐篇演绎提炼

把“每篇文案的独特演绎路径”与“多篇文案的共性骨架族”同时保留。抽象用于检索，单篇卡用于高保真迁移。

## 开始前

完整读取 [单篇演绎卡协议](references/source-skeleton-schema.md)，使用 [单篇演绎卡模板](assets/source-skeleton-template.md) 生成卡片。

开始前先读：

1. 本次要处理的原始参考文案；
2. ‘【06.知识库】/skeletons/骨架库总览.md’；
3. 可能相关的既有骨架族文件；
4. ‘【06.知识库】/skeletons/演绎样本索引.md’（存在时）。

## 存放位置

- 单篇演绎卡：‘【06.知识库】/skeletons/source-cards/RS<number>_<name>.md’
- 骨架族：保留在 ‘【06.知识库】/skeletons/’ 根目录，沿用 A2、C6 等稳定 ID
- 样本索引：‘【06.知识库】/skeletons/演绎样本索引.md’

## 工作流

### 1. 确定单篇单元

一篇独立成立的文案对应一张 source-skeleton 卡。一个文件包含多篇独立文案时，按标题、编号或段落定位分拆成多张卡，共享 source_path，各自填写 source_locator。

放入以下目录的文案默认视为用户已筛选的 curated 形式参考：

- ‘【03.参考资料】/文案参考/’
- ‘【03.参考资料】/账号参考/’

curated 代表可用于学习演绎方式，不代表其中的数据、事实或跨平台效果已经验证。

### 2. 还原原文演绎轨迹

按真实出现顺序记录每个段落：

- 这一段说了什么；
- 它完成什么演绎任务；
- 观众为什么愿意继续；
- 与上一段如何连接；
- 给下一段制造了什么缺口、期待或信任。

不要把整篇压缩成“反常识 → 举例 → 升华”一行公式。

紧接着提炼“流量机制签名”：首句具体做了什么、观众为什么停、留下什么未闭合问题、正文在哪里兑现、需要哪些证据。必须依据原句描述，不能把没有数字的开头标成“强数字钩子”，也不能只写“警告、反常识、制造悬念”等通用标签。

### 3. 保留关键表达锚点

选取最能代表原文手艺的短表达、转折、追问、细节、类比或收刀方式，每条同时记录“原文锚点”与“功能”。

锚点用于内部学习，成稿时不得长段复制。如果抽象后无法说明原文为什么好，回到原文补记，不用空泛术语代替。

### 4. 区分不可压缩的差异

即使归入同一骨架族，也必须写明这篇与其他成员不同的：

- 开口动作；
- 信息释放次序；
- 情绪曲线；
- 证据出现时机；
- 转折类型；
- 收束与行动承接。

### 5. 链接骨架族

先判断是否存在适配的既有骨架族：

- 存在：填写 pattern_family_ids，并在骨架族的“单篇样本”中增加链接；
- 部分适配：可同时链接 1–2 个骨架族，写明各自负责的段落；
- 不适配：标记 family_status: new-candidate，不强塞进旧分类。

骨架族只是导航和共性概括。新文案与旧文案同类，也不得省略单篇卡。

### 6. 标注精选与表现证据

- `curation_status` 回答样本是否经过人工筛选；同时写 `curation_basis`。
- `performance_status` 只回答真实发布表现，必须与精选判断分开。
- 没有平台、指标、统计窗口和样本量时写 `unknown`，不得因用户把文案收入参考库就写成 `verified`。
- 有表现反馈时在“表现证据”记录原稿还是迁移稿、数据路径和复验情况。

### 7. 更新索引与账本

1. 在《演绎样本索引》中新增来源、样本 ID、骨架族、赛道、平台和状态。
2. 在 ingest log.md 中记录处理数、新卡、新骨架族候选和待处理项。
3. 如已有全局共享资产账本，以 source-skeleton:RS<number> 登记单篇卡，以 pattern-family:<ID> 登记骨架族。

### 8. 验证

~~~bash
python3 scripts/validate_source_skeleton.py --file "<RS卡路径>"
python3 scripts/validate_source_skeleton.py --dir "<source-cards目录>"
~~~

修复所有错误。警告需要人工判断是否过度抽象、锚点不足或归类太宽。

## 与写作 Skill 的接口

- cross-source-writer 先完成正文价值契约，再检索 RS。默认选择 1 张主 RS，确有互补功能时再加 1 张辅助 RS；不把 3 张卡混成一条模糊路径。
- 候选蓝图必须标明参考的 RS 卡、借用的演绎动作和不得复制的事实。
- 使用前完成 RS Fit：正文主张、受众识别、证据门槛、信息释放、兑现位置和平台节奏至少五项适配；只因“开头很炸”不得选用。
- `performance_status: unknown` 只能形成流量假设，不能称为“有流量结构”或“验证过的开头”。
- 成稿时迁移注意力路径和表达功能，不复制来源人物、案例、数据、身份或长段原文。
- opening-copy-reviewer 检查成稿的开头和演绎是否与当前正文一致，不把 RS 卡当作必须照抄的模板。

## 禁止项

- 多篇同属一种反常识、故事或清单形式就只保留一张卡；
- 只留“开头、中间、结尾”或一行抽象公式；
- 删除原文中关键转折、问法、类比、细节、节奏和收刀方式；
- 把参考文案里的事实、立场、人设或客户案例当成当前 IP 的证据；
- 为提高数量把同一篇文案的连续段落拆成多张卡；
- 将 curated 写成“已证明高播放”或“适合所有赛道”。
