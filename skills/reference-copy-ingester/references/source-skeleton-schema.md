## 核心定义

source-skeleton 是一篇独立参考文案的演绎记录。它保留这篇文案如何分配注意力，而不是只提炼一个可跨文案复用的共性公式。

一篇参考文案可以归入一个既有骨架族，但归类不得代替单篇卡。

## Frontmatter

~~~yaml
type: source-skeleton
source_skeleton_id: RS001
name: ""
source_path: "【03.参考资料】/文案参考/...md"
source_locator: "全文"
source_format: short-video
source_platform: ""
source_industry: ""
pattern_family_ids: [A2]
family_status: existing
curation_status: curated
curation_basis: user-selected-reference
performance_status: unknown
performance_evidence_paths: []
transfer_scope: global-method
tags: []
created: 2026-07-21
updated: 2026-07-21
~~~

### 字段规则

| 字段 | 规则 |
|---|---|
| source_skeleton_id | 全局稳定 RS<number>，停用后不复用 |
| source_path | 只填原始参考文案路径，不填摘要或 AI 草稿 |
| source_locator | 全文或文件内的标题、编号、时间码、行号 |
| pattern_family_ids | 0–2 个骨架族 ID；无适配族时留空 |
| family_status | existing、new-candidate、unclassified |
| curation_status | curated、candidate、retired |
| curation_basis | 为什么认为值得学习，例如 user-selected-reference、editor-reviewed、agent-candidate |
| performance_status | unknown、signal、verified；没有数据时不得写 verified |
| performance_evidence_paths | 支撑表现判断的发布记录或反馈路径；unknown 时可为空 |
| transfer_scope | 固定 global-method；表示只共享演绎方法，不共享事实 |

## 必需正文

### 1. 来源与适用边界

说明原始对象、平台、内容任务、可迁移部分和不可迁移事实。

### 2. 原文演绎轨迹

使用表格顺序记录：

| 节点 | 原文内容摘要 | 演绎任务 | 连接动作 | 为什么继续看 |
|---|---|---|---|---|

节点数由原文决定，不强行统一为三段或五段。

### 3. 注意力推进

写清：

- 最初的注意力来源；
- 中段如何防止观众离开；
- 何时给答案，何时继续制造缺口；
- 证据、细节、情绪和权威如何轮换；
- 收束时观众获得什么。

### 流量机制签名

每张新卡都应记录：

| 字段 | 回答的问题 |
|---|---|
| 首句动作 | 首句逐字意义上做了什么，而不是套什么钩子名 |
| 受众识别 | 谁会立即觉得与自己有关 |
| 停留理由 | 观众为什么不在首句后划走 |
| 未闭合问题 | 首段留下什么待回答的信息 |
| 兑现位置 | 正文在哪个节点偿还开头 |
| 证据节奏 | 判断、场景、数字、案例、清单如何轮换 |
| 最低素材门槛 | 迁移时正文必须拥有的事实或证据 |
| 失效条件 | 哪些主题、平台或证据状态下会写成标题党 |

这是“怎么获得注意力并偿还注意力”的可迁移签名，不等于真实流量证明。真实表现仍只由 `performance_status` 与表现证据裁决。

### 4. 关键表达锚点

至少保留 2 个能代表原文手艺的短锚点：

| 原文锚点 | 位置 | 功能 | 可迁移手艺 | 不可照搬内容 |
|---|---|---|---|---|

优先保留转折、追问、信息顺序、重复、细节堆叠、反转、类比和收刀，不只保留一句醒目的标题。

### 5. 不可压缩的差异

说明这篇文案与同骨架族其他样本相比，哪些节奏、顺序、情绪、证据或表达方式不能被一行公式取代。

### 6. 迁移规则

区分：

- 必须保留的功能顺序；
- 可换成当前 IP 内容的槽位；
- 当前正文必须具备的证据；
- 不适用的选题、素材或平台情况。

### 7. 骨架族归属

记录归入哪个骨架族、符合哪些共性，以及与该族已有样本的差异。无适配族时写“新骨架族候选”和建议名称。

### 8. 表现证据

分别写明：

- 为什么进入精选库；
- 是否存在真实发布数据；
- 平台、指标、统计窗口和样本量；
- 数据对应原参考文案，还是迁移后的新稿；
- 无数据时明确写“仅人工精选，表现未知”。

## 抽象与保真标准

合格单篇卡必须让未重读原文的写作 Agent 仍能回答：

1. 观众在每个节点为什么继续；
2. 原文最独特的两个以上表达动作是什么；
3. 同属一个骨架族时，这篇与其他样本有什么不同；
4. 迁移到新内容时需要什么证据；
5. 哪些只属于来源人物，不得迁移。
6. 首句为什么让目标观众停留，正文在哪一处兑现。

只有类型名、一行公式和通用仿写模板的卡不合格。

## 骨架族关系

- 单篇卡是不可合并的原子资产。
- 骨架族是多对多导航层，一张卡最多归入两个族。
- 同一骨架族下必须保留样本差异，不做“一族只留一篇代表作”。
- 一篇文案只因开头同类，但中段和收束不同，仍然是不同单篇卡。

## 表达锚点边界

- 原文锚点优先使用短句或局部片段，只保留分析所必需的长度。
- 使用锚点时保留来源路径与定位。
- 成稿不得因为存在内部锚点就复制原文长段。
- 有授权、引用或署名要求时，按原来要求执行。
