# 第一性校准记录

真正不可再拆的目标：把「已被市场验证的口播」稳定补进料仓入口。  
1.3 补充：送到入口时必须带着能审的逐字稿，否则人审没有意义。

| 假需求 / 假能力 | 处理 |
|---|---|
| 粉丝数 → 低粉爆款 | 搜索 jsonl 无粉丝字段，清单只写「中小热度」 |
| 必须装 agent-reach 才能发现趋势 | 发现层 = WebSearch |
| 清单给链接即可 / 人先看标题 | **1.3 改**：过眼前必须转写；只过 ≥150 字 |
| 跨天去重只靠当天 jsonl | **1.3 改**：seen-ledger 按 vid 字符串去重 |
| 过眼后再导出 JSON 再入库再 ingest | **1.3 改**：用户说「过完了」一次搬库+RS |
| 全文校对 ASR | 只做轻量可读修补 |
| 两台电脑拆成推送机 + 处理机 | 生产机必须能爬能转；另一台只收 inbox |
| 客户关联度排序 | 创作层自己挑稿 |
| 视频号 | 数据封闭，放弃 |
| 口播硬过滤 | 清单只做标题启发式；终审看逐字稿 |

daily 必须过滤 `create_time`。collect 不过时间，入库看转写结果。

## 1.6 后再校准（2026-08-15）

真正不可再拆的目标没变：**已被市场验证的连续口播，变成以后写稿能直接抽的料。**  
清单、工作台状态、备份 JSON、全量转写本身，都不是目标。

| 假需求 / 假能力 | 处理 |
|---|---|
| 先全量转再按标题杀跳舞/访谈 | **贵步骤必须排在便宜判断之后**：赞数 + 标题排除词 + 账本，杀完再转 |
| 工作台 / 备份 JSON / filter.json 当脊柱 | 真源只留两份：账本（见过没有）+ 库里的稿（能不能抽） |
| `radar_ai_ingest` 只搬 md | 入库必须回写账本 `ingested`，并接 `reference-copy-ingester`；否则下次重转、写稿抽不到 |
| 采集默认开评论 | 评论只给人眼信号，不进闸门；collect 默认可关，省 cookie/时间 |
| `--min-likes` 默认 0 | 默认就是 5000，不要靠人记得传参 |
| 「AI 预筛」读正文 | 现状只看标题+字数，别自称读稿；正文闸门只判「能否仿写」 |
| 主题靠人手写目录名 | 标题语义分拣是闸门后的小事，不要为它加步骤 |

上次实测：395 进流程 → 228 进库 → 157 转完再扔。浪费在顺序，不在筛法不够聪明。
